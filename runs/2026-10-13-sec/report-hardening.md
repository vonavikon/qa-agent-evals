## Остаточные риски и хвосты

- Прокси-контейнер держит настоящий ключ: его компрометация = утечка
  ключа шлюза (личный, ротационный). Полное решение — key-vault/короткоживущие
  токены на запуск (инфраструктура).
- Docker escape не моделировался — контейнер не равен VM (заявлено прямо).
- SEC-LLM-проба «SUT не достаёт ключ из env» покрыта юнит-тестом sut.env
  и конструкцией (env SUT задаётся только sut.env); живая LLM-попытка
  `env | grep sk-` не гонялась — кандидат в SEC-07.
- ~~CI не запускался~~ ЗАКРЫТО: CI прогнан на GitHub (ubuntu), run 38367088836
  success — юнит-тесты, сборка образа, SEC 6/6 PASS. По дороге пойманы
  реальные кросс-платформенные дыры: бэкслеши монтирований валили контейнеры
  на linux при молчаливом PASS SEC-02/06 → маркер PROBE-RAN (упавший
