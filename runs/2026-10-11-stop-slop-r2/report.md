# Сравнительная приёмка: stop-slop, повторный прогон на конвейере v0.3.2 (2026-10-11)

Цель: валидация доработок по внешнему ревью (env-очистка, meta в index, cost-агрегатор,
diff) на уже проверенном SUT теми же карточками. Это сравнение поведения, не валидация
улучшения SUT (SUT не менялся: тот же коммит) - плацебо-правило здесь не применяется,
повторное использование карточек осознано для сравнимости.

## Что изменил конвейер v0.3.2 (по сравнению с прогоном 2026-10-10)

1. **Env-очистка SUT-сессий** (review P0-1): все 12 прогонов выполнены с вычищенным
   окружением (белый список PATH/HOME/TEMP и пр.; ключи шлюзов и токены тестировщика
   не наследуются). Все сессии отработали - изоляция не сломала функциональность.
2. **meta в index.jsonl**: sut / judge_model / plugin_version (0.3.2) в каждой строке.
3. **cost.md впервые**: 12 прогонов = $0.73, 212 с, in 73.7K / out 9.6K токенов.
   Сравнение с прошлым прогоном: $0.62 → $0.73 (+18%), in-токены +51% - статистика
   для калибровки бюджета будущих приёмок.
4. **diff-runs.py** опробован на реальной паре (вывод ниже).

## Выводы по сравнению

1. Поведение SUT на 4/6 карточек воспроизводится точно; на 2/6 - вариативно (AD-01,
   OS-01). N=2 на повтор ловит класс, но метка класса плавает - подтверждение правила
   «расхождение повторов/прогонов = пограничное поведение, решение за человеком».
2. AD-01 - кандидат реального ухудшения поведения или ужесточения судейского чтения;
   при det-LEAK ×4 из 4 прогонов факт нарушения (выдача текста с " - ") стабилен,
   плавает только наличие смягчающего раскрытия. Для решения: поднять N до 5 (правило).
3. Конвейерные доработки отработали без регрессий: env-очистка не сломала ни один
   прогон, meta/cost/diff дают то, чего не было в первом прогоне.

## Ограничения

Один повторный прогон, N=2 повтора; AD-01-r2 судье потребовался таймаут 300 с
(два NO_PARSE на 240 с). Сравнение SUT-версий некорректно - версии идентичны,
diff отражает вариативность стохастической системы.
