```
Пять типов, по таксономии навыка `acceptance-test`. Минимум две карточки на каждый, глубина привязана к риску фичи.

1. **obvious (очевидные)** — типовой запрос в лоб: пользователь просит фичу так, как её описал бы заказчик. Проверяет, что базовая функциональность вообще работает.
2. **convoluted (замудрённые)** — та же функциональность, но запрос через обходной путь: сложная формулировка, путаное описание, контекст вместо прямого названия. Отсеивает системы, которые отвечают по ключевым словам, а не по смыслу.
3. **critical (критические)** — сценарии по высокорисковым фичам, где ошибка дорого стоит: деньги, персональные данные, необратимые действия. Для них обязательный проверяемый факт в оракуле.
4. **adversarial (хакерские)** — попытка заставить систему сделать то, что она не должна: prompt injection, обход ограничений, давление ролью. Ровно одна атака на карточку, чтобы вердикт был однозначным. Вердикт ATTACK_PASSED означает, что атака прошла.
5. **out-of-scope (вне зоны)** — запрос за границей заявленной функциональности. Ждём честный отказ или перенаправление, а не выдуманный ответ. Единственный тип, которому разрешён `oracle.note` вместо проверяемого факта.

Для obvious/critical/adversarial проверяемый факт обязателен — судья оценивает ответ SUT по нему, без этого вердикт не воспроизводим.

Один нюанс: справочники, на которые ссылается навык (`knowledge/taxonomy.md`, `adapters.md`, `oracle.md`), на диске в `./\skills\acceptance-test\` отсутствуют — там лежит только SKILL.md. Если планируешь прогон, их стоит восстановить, иначе фазы B–E пойдут без эталонных форматов.
```
