## Что может произойти на самом деле — три реальных канала

1. **Аналитик (фаза A).** Инструменты Read/Glob/Grep позволяют ему прочитать *любой* файл под каталогом SUT — не только скиллы и README. Если рядом с кодом SUT лежат дампы, базы, логи с клиентскими данными, он их увидит и может процитировать фрагменты в профиль (`runs/<дата>-<sut>/профиль.md`). Запретительного списка нет.

2. **Ответы SUT → протоколы.** Если тестируемая система сама опирается на реальные клиентские данные (RAG по клиентской базе, CRM-ассистент), то её ответы на реплики исполнителя записываются в протоколы дословно: `runs/<дата>-<sut>/протоколы/<id>.md`. Это главный канал: клиентские данные изнутри SUT → файлы прогона. Санитизации/маскирования PII в фреймворке нет.

3. **Файлы прогона → git.** Сейчас артефакты лежат в `./\runs\` — у этого репо нет remote, файлы untracked, никуда не уходят. Но `runs/` не привязан к абсолютному пути: если запустить приёмку из cwd vault автора, артефакты окажутся в рабочем дереве vault, а `.gitignore` vault их **не** игнорирует — привычный «перед концом сессии git add + commit + push» утащит протоколы на GitHub. Этот риск в доках не оговорён.

Плюс один фоновый факт: все реплики и ответы проходят через шлюз провайдера модели (в текущем сетапе — api.z.ai), как и любой ваш диалог с Claude Code. Содержимое диалогов покидает машину в LLM-API — новых внешних маршрутов в v0.1 нет.

## Вердикт

Самопрогон фреймворка это честно фиксирует: «Контроль отдан инструкциям субагентов, не механизмам» (`runs\2026-10-08-qa-agent-evals-selftest\профиль.md`) и «транскрипты в runs/ — канал утечки содержимого диалогов через репозиторий прогона».

**Безопасно, если:** (1) SUT — тестовый контур без реальных клиентских данных внутри, и рядом с его кодом нет дампов/баз; (2) приёмка запускается из cwd `qa-agent-evals`, а не из vault. **Небезопасно, если** SUT ходит в реальную клиентскую базу — тогда её ответы лягут в протоколы дословно, и прогон из vault-каталога может отправить их в git.

Два дешёвых укрепления, если планируешь прогон по системе с реальными данными: добавить `runs/` в `.gitignore` vault и указывать аналитику конкретные каталоги SUT, а не корень. Оба — одна строка, механизмов не требуют. Сделать?
