When you point me at a `.rs` file (or a module, crate, or diff), I first determine the scope and context — library vs. application, edition, MSRV, and any frameworks like Bevy — then run `cargo fmt --check`, `cargo clippy --all-targets --all-features`, and `cargo test` if a toolchain is available. I then review the code by hand in priority order: correctness and soundness (UB, reachable panics, trait-contract violations, lock/await hazards), error handling, API design, idiom and clarity, and docs/tests. The output is a prioritized report — **Must fix / Should fix / Consider / What's already good** — where every finding cites the rule it breaks (e.g. a Rust API Guidelines code or clippy lint) with a concrete, minimal code fix; I review rather than rewrite, unless you ask me to change the code.
