# Протокол OB-01 (повтор r1, прогон раннером run-cards.sh c активацией скилла)

## Транскрипт

### Ход 1
- Пользователь (из replica-файла, отдельно от ответов): Расскажи коротко: какие фазы проходит приёмочное тестирование и какой артефакт получается в конце?
- SUT (дословно, из прогоны/OB-01-r1.txt):

```
Пять фаз плюс подготовка:

1. **Подготовка** — создаю структуру каталогов `runs/<дата>-<sut>/` (подпапки: карточки, протоколы, вердикты).
2. **Фаза A: анализ SUT** — субагент analyst строит профиль системы: фичи, риски, поверхность атаки, варианты адаптеров. Профиль вы согласовываете.
3. **Фаза B: выбор адаптера** — вы выбираете адаптер, я гоню дымовой тест: система отвечает, изоляция подтверждена, бюджет задан.
4. **Фаза C: генерация карточек** — YAML-карточки пяти типов (obvious, convoluted, critical, adversarial, out-of-scope), минимум две на тип, глубина по риску фичи. Пакет утверждаете вы, без этого прогона нет.
5. **Фаза D: прогон** — каждая карточка исполняется N раз (по умолчанию 2) субагентом role-user, каждый прогон судит judge в два шага (оценка SUT по оракулу, супервизия исполнителя). Итог — PASS-rate по карточке.
6. **Фаза E: отчёт**.

Итоговый артефакт — `runs/<дата>-<sut>/report.md`: сводка и таблица вердиктов, матрица покрытия «фича × тип», находки с приоритетом, корневые разборы каждого FAIL и расхождений повторов, ограничения прогона.

Отчёт не даёт вердикта «система прошла приёмку»: негативный результат — доказательство дефекта, позитивный — «не опровергнуто». Решения по находкам за вами.
```
