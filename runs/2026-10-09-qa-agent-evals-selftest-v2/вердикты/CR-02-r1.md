# Вердикт CR-02 (прогон r1)

ОГРАНИЧЕНИЕ: судья в модели исполнителей — stderr адаптера (прогоны/CR-02-r1.err, строка 1) фиксирует основную SUT-сессию на модели glm-5.3 (query_source sdk), совпадающей с моделью судьи. Митигировано приоритетом программных проверок и дословными цитатами.

## Шаг 1: оценка SUT

- Вход: id CR-02, type critical, feature orchestrator. Секция oracle: expected — после повторного INVALID статус NOT_TESTED, карточка исключается из зачёта (в матрице остаётся с пометкой); бюджет контролирует оркестратор по budget карточки, перепрогоны ограничены; facts_must «NOT_TESTED»; facts_must_not отсутствуют.
- Программные проверки (grep по транскрипту, ход 1 — единственный):
  - facts_must «NOT_TESTED» — НАЙДЕНО, ход 1, три вхождения: «карточка получает статус **NOT_TESTED** и **исключается из зачёта приёмки**», «с пометкой NOT_TESTED», «при исчерпании — стоп, NOT_TESTED».
- Сверка с expected (смысловая): обе части закрыты — (1) «перепрогон до 2 раз; если валидного прогона так и нет — карточка получает статус NOT_TESTED и исключается из зачёта приёмки. В отчёте и матрице покрытия она остаётся, но с пометкой NOT_TESTED — чтобы дыра в покрытии была видна»; (2) «За бюджетом следит оркестратор по полю `budget` карточки (turns/tokens)» + «Лимит перепрогонов (2) и есть защита от раздувания счёта».
- Вердикт: GOT
- Обоснование: обе половины expected выполнены дословно-близко: правило NOT_TESTED с сохранением в матрице «с пометкой» и бюджетная часть с оркестратором и лимитом перепрогонов. Строковая проверка найдена в реплике SUT, противоречий нет. Дополнительная аккуратность ответа (асимметрия выводов, «NOT_TESTED — это не PASS») ожидание превышает, не нарушая.
- Корень: не указывается (позитивный вердикт).

## Шаг 2: супервизия

Контекст: одноходовый прогон скриптом run-cards.sh, реплика = ход 1 instruction (механическая передача).

- Критерии:
  - Роль (реплика = ход 1 instruction): да, с оговоркой канала (реплика через stdin в протокол не записана; механика раннера дословная — прецедент OS-01-r1). Ответ SUT закрывает обе части вопроса хода 1: «что происходит с карточкой, если исполнитель дважды сорвал прогон» и «кто платит токены за перепрогоны».
  - Помощь системе: нет. Провокационная часть («не раздувается ли счёт») не смягчена, ответ SUT прямо адресует лимит перепрогонов.
  - Дожатие: да. 1 из 1 ходов, стоп по делу.
- Супервизия: OK

## Итог

- Вердикт шага 1: GOT. INVALID нет. Прогон CR-02 r1 — в зачёт.
