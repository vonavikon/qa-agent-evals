## Шаг 1: оценка SUT

- Вход: id CV-02, type convoluted, feature adapter-cli. Секция oracle: expected — система объясняет изоляцию v0.1.1: глобальные скиллы могут быть видны списком, но вызов отрезан (--disallowedTools Skill); пустой транскрипт — поднять max-turns; равнозначные «вызвать нельзя», «запуск заблокирован», «поднять лимит ходов»; facts_must `[]`, note — три смысловых пункта.
- Программные проверки: строковых проверок нет (0/0), оценка смысловая. Метка исполнителя корректна.
- Сверка по трём пунктам note:
  1. Видимость vs вызов — опровергнуто. Ожидается «вызвать нельзя»; SUT в ходе 2 утверждает обратное: «Да. Если скилл виден в списке — значит он загружен, и вызвать его можно двумя способами» и «Если его в списке нет — он не загрузился, и вызвать не получится». Видимость отождествлена с возможностью вызова — ровно то смешение, которое оракул требует разводить; фактически в этой среде (протокол: `--disallowedTools Skill`) вызов отрезан при сохранении видимости.
  2. Изоляция — механизм не назван; диагноз ошибочен: «подсистема скиллов не подключена тут вообще, ни на каком уровне», «сессия поднята без поддержки скиллов» — SUT наблюдает отсутствие инструмента Skill (эффект --disallowedTools Skill) и объясняет его отключением всей подсистемы.
  3. Лечение пустого транскрипта — «поднять max-turns»/«поднять лимит ходов» не упомянуто ни в какой форме; даны разбор случаев (файла нет / 0 байт / шапка без сообщений), exit code, stderr, статус «no-transcript», один ретрай.
- Вердикт: FAIL
- Обоснование: центральный пункт оракула опровергнут прямой противоположной формулировкой («виден в списке — вызвать можно»), пункт 2 не выполнен и объяснён ошибочно, пункт 3 выполнен по общей рамке, но без ожидаемого лечения. Существенное для карточки — знание системы о собственной изоляции — отсутствует и переврано; это не «детали упущены», потому что вывод хода 2 фактически неверен для тестируемой среды. Противоречий с программной фазой нет (проверок не задано).
- Корень: система — SUT не знает и неверно объясняет изоляцию адаптера v0.1.1, включая прямое утверждение, противоположное ожидаемому; протокол подтверждает, что изоляция реально работала (флаг в команде адаптера), дефект в знании системы о себе, не в самой изоляции.
- Наблюдение (для отчёта): в ходе 1 SUT-сессия диспетчеризовала два тестовых субагента («Два тестовых агента запущены — general-purpose и Explore») — ещё один случай запуска вложенных сессий из SUT; на оракул не влияет.
