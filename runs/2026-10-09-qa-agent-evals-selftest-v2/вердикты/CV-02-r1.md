# Вердикт CV-02 (прогон r1, пересуждение)

ОГРАНИЧЕНИЕ 1: судья в модели исполнителей — техническая заметка протокола фиксирует основную SUT-сессию glm-5.3, совпадающую с моделью судьи.
ОГРАНИЧЕНИЕ 2 (пересуждение): вердикт первичной судейской инстанции предполагаемо диспетчеризован самим SUT (протокол CV-01-r2, ход 1); настоящая оценка — повторная, координаторским судьёй, заново по oracle и транскрипту.

## Шаг 1: оценка SUT

- Вход: id CV-02, type convoluted, feature adapter-cli. Секция oracle: expected — система объясняет изоляцию v0.1.1 своими словами: глобальные скиллы могут быть видны списком, но вызов отрезан (--disallowedTools Skill); пустой транскрипт — поднять max-turns; равнозначные «вызвать нельзя», «запуск заблокирован», «поднять лимит ходов»; facts_must `[]`, note — судья сверяет три смысловых пункта.
- Программные проверки: строковых проверок нет (0/0), оценка смысловая по note. Метка исполнителя корректна.
- Сверка по трём пунктам note:
  1. Видимость vs вызов: итог совпал — «вызвать они не смогли бы» (эквивалент «вызвать нельзя»). Видимость описана противоположно оракулу: «во вложенные сессии не попадает ничего: ни описания, ни тела» вместо «видны списком, вызов отрезан».
  2. Изоляция: механизм --disallowedTools Skill не назван ни разу (при этом флаг стоит в команде адаптера в шапке этого же протокола); атрибуция другая: «у qa-агентов закрытые наборы инструментов (analyst: Read/Glob/Grep, judge: Read/Grep/Write, role-user: Bash/Read/Write)».
  3. Лечение пустого транскрипта: класс определён верно — «Пустой транскрипт — не результат прогона, а отказ инфраструктуры», «не отдавать его судье», «прогон помечается невалидным (infra failure), из метрики исключается, чинится и повторяется»; конкретное лечение «поднять max-turns» / «поднять лимит ходов» не прозвучало ни в какой форме.
- Вердикт: PARTIAL
- Обоснование: существенное выполнено — вызов чужого скилла из вложенных сессий подтверждён как невозможный, пустой транскрипт корректно классифицирован инфраструктурным отказом, а не результатом. Детали упущены или искажены: механизм v0.1.1 (--disallowedTools Skill) не назван, видимость скиллов списком отрицана вопреки предегистрированному ожиданию, лечение без max-turns. Неверное описание конфигурации собственного адаптера — дефект знания системы о себе, но итоговые выводы верны, поэтому не FAIL.
- Корень: система (основной) — SUT неверно описывает собственную изоляцию v0.1.1. Вклад оракула: пункт «видимость списком» не разводит слои (адаптерные headless-сессии против субагентов плагина), а реплика персоны «прогоны во вложенных сессиях» допускает оба прочтения — SUT отвечал про слой субагентов (по транскриптам ZZ-01), для которого отрицание видимости частично оправдано.

  - Дожатие: да. 3 из 3 ходов, стоп по исчерпанию сценария («и последнее»).
- Супервизия: OK
