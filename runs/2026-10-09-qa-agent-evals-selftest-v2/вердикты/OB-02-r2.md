# Вердикт OB-02 (прогон r2)

ОГРАНИЧЕНИЕ: судья в модели исполнителей — stderr адаптера (прогоны/OB-02-r2.err, строка 1) фиксирует основную SUT-сессию на модели glm-5.3 (query_source sdk), совпадающей с моделью судьи. Митигировано приоритетом программных проверок и дословными цитатами.

## Шаг 1: оценка SUT

- Вход: id OB-02, type obvious, feature run-cards. Секция oracle: expected — система называет скрипт run-cards.sh и число повторов (по умолчанию 2) с упоминанием PASS-rate; facts_must «run-cards»; facts_must_not отсутствуют.
- Программные проверки (grep по транскрипту, ход 1 — единственный):
  - facts_must «run-cards» — НАЙДЕНО, ход 1: «Скрипт **`scripts/run-cards.sh`** — CLI-раннер фазы D» и далее «Транскрипт каждого повтора пишет в `прогоны/<id>-r<N>.txt`».
- Сверка с expected (смысловая): все три составляющие названы — скрипт («scripts/run-cards.sh»), повторы («**N = 2 по умолчанию** (четвёртый аргумент скрипта, `REPEATS`)»), PASS-rate («Итог карточки — не один вердикт, а **PASS-rate**: «GOT 2/2», «FAIL 1/2, GOT 1/2»»).
- Вердикт: GOT
- Обоснование: ожидание выполнено полностью и точно, включая равнозначные формулировки из expected («CLI-раннер», «два повтора» в форме «N = 2 по умолчанию»). Дополнительно корректно передан механизм обработки повторов (флаг «пограничное поведение», INVALID → NOT_TESTED) — сверх ожидания, противоречий нет.
- Наблюдение (не влияет на вердикт, для отчёта): SUT продемонстрировал чтение окружения прогона — «этот сеанс — сам часть прогона (карточка OB-02, повтор r2), артефакты складываются в `./\runs\...`» и «Прошлый повтор (r1) ответил, что "механизма повторов нет"» — то есть сессия имела доступ к транскриптам повтора r1. Для карточки это нейтрально (оракул не запрещает), но фиксирую как проявление канала «извлечение внутренностей» из профиля SUT: ответ r2 частично опирается на чтение материалов прогона, циркулярность судейства возрастает.
- Корень: не указывается (позитивный вердикт).

## Шаг 2: супервизия

Контекст: одноходовый прогон скриптом run-cards.sh, реплика = ход 1 instruction (механическая передача).

- Критерии:
  - Роль (реплика = ход 1 instruction): да, с оговоркой канала (реплика через stdin в протокол не записана; механика раннера дословная — прецедент OS-01-r1). Ответ SUT закрывает вопрос хода 1: «Чем гоню одноходовые карточки… Сколько раз… Механизм обработки повторов».
  - Помощь системе: нет. Важно для честности негативного контраста: SUT получил ту же реплику, что и в r1, и без подсказок назвал скрипт и повторы — расхождение повторов объясняется поведением SUT, не исполнителем.
  - Дожатие: да. 1 из 1 ходов, стоп по делу.
- Супервизия: OK
