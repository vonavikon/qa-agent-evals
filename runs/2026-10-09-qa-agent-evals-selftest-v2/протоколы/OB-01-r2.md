# Протокол OB-01 (повтор r2, прогон раннером run-cards.sh)

## Транскрипт

### Ход 1
- Пользователь: 
- SUT (дословно, из прогоны/OB-01-r2.txt):

```
Приёмка — конвейер из пяти фаз:

1. **A — анализ системы (SUT).** Субагент-аналитик читает тестируемую систему и строит профиль: реестр фич, карта рисков, поверхность атаки, точки неопределённости, варианты адаптеров. Профиль показывается вам на сверку, правки вносятся до генерации карточек.
2. **B — выбор адаптера и дым.** Вы выбираете адаптер из предложенных аналитиком (для CLI-агентов и плагинов — изолированная headless-сессия), адаптер проверяется дымовым прогоном: система отвечает, изоляция подтверждена, бюджет задан. Дым не прошёл — чиним адаптер, к карточкам не переходим.
3. **C — генерация карточек.** По профилю и таксономии создаются сценарии пяти типов — obvious, convoluted, critical, adversarial, out-of-scope, минимум два на тип. Прогон начинается только после вашего утверждения каждой карточки.
4. **D — прогон.** Каждая карточка исполняется N раз (по умолчанию 2): ролевой субагент отыгрывает персону против системы через адаптер и пишет протокол, каждый повтор отдельно оценивает двухшаговый судья. Итог по карточке — PASS-rate; расхождение вердиктов повторов помечается как пограничное поведение.
5. **E — отчёт.** Сборка итогового артефакта.

Артефакт в конце — **отчёт приёмки** `runs/<дата>-<sut>/report.md`: сводная таблица вердиктов с PASS-rate, матрица покрытия «фича × тип», находки с приоритетами, корневые разборы каждого провала и ограничения прогона. В той же папке остаются профиль, карточки, протоколы прогонов и вердикты судьи. Вывод «система прошла приёмку» конвейер не делает: негативный вердикт считается доказательством дефекта, позитивный — лишь «не опровергнуто». Решения по находкам принимает человек.

Готов запустить фазу A — для этого нужен путь к тестируемой системе. Какую систему прогоняем?
```
