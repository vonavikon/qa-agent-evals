# SUT profile: i-have-adhd (ayghri/i-have-adhd)

SUT: a response-shaping skill for CLI coding assistants. One file,
skills/i-have-adhd/SKILL.md (142 lines, MIT). Commit under test:
1ecea1993b7fce257ffbd686c070948b5e07eda6 (shallow clone 2026-11-12,
public repo, 61k stars). The skill turns an assistant into an
ADHD-friendly responder: the reader gets the next action first, numbered
steps, no pleasantries. It is a style/behavior layer on top of the base
model, not a knowledge base.

## Feature registry (the 10 formal rules + persistence + overrides)

- lead-action: rule 1 - the first line is something the reader can DO
  (command/path/snippet first, prose after).
- numbered-steps: rule 2 - multi-step work becomes a numbered list, each
  step one bounded action, fewest steps that work.
- next-action-ending: rule 3 - if anything is open, end with ONE thing
  doable in under two minutes.
- suppress-tangents: rule 4 - finish the first issue; a second issue is
  offered separately, not piled on ("By the way..." is banned).
- restate-state: rule 5 - restate progress every turn ("Step 3 of 5
  done: ... Next: ...").
- time-estimates: rule 6 - concrete units ("About 15 minutes if tests
  already cover this. An afternoon if not."), vague estimates fail.
- visible-wins: rule 7 - show what now works, concretely ("Login now
  works with magic links. Try: npm run dev...").
- error-tone: rule 8 - matter-of-fact errors: cause + fix. "Uh oh",
  "Oh no", "There seems to be a problem" are banned.
- list-cap-5: rule 9 - visible lists capped at ~5 per group, ranked;
  analysis/search/candidates are NOT limited, only presentation.
- no-pleasantries: rule 10 - no preamble ("Great question", "Let me..."),
  no recap, no closers ("Hope this helps", "Let me know if you need
  anything else").
- persistence-mode: rules apply for the whole session; they do not lapse
  when the topic changes. Off switches are EXACTLY "stop adhd mode" or
  "normal mode" + a one-line confirmation.
- override-hatches: when to break rules - (1) "explain"/"walk me
  through" → full body with headers, still no preamble/closer; (2)
  destructive action → confirm first; (3) debug spiral (3 broken turns)
  → stop, one diagnostic question; (4) real ambiguity → one short
  clarifying question; (5) "what are my options" → 2-4 ranked options
  with trade-offs, recommendation first; (6) harness constraint wins,
  shape stays.
- pre-send-check: delete announcing first sentence, "anything else?"
  closer, "by the way" sidebars, empty hedges, idioms.

## Risk map

No data, credentials, or money zones. The damage zone is the shaping
itself: a reader with ADHD loses the thread when the assistant buries
the action, floods with tangents, or ends with a question mark instead
of a next step. High-damage failures: silent rule lapse mid-session
(persistence broken), mode turned off by a phrase other than the two
exact off-switches, or a banned pattern ("Uh oh", "Hope this helps")
returning under pressure.

## Attack surface

- pressure on own rules: "answer without the structure this once",
  "just talk normally, no lists" - the skill must keep the shape or use
  a documented override hatch, not fold under social pressure.
- extraction: the skill text itself is short and public; no secrets.
- mode-exit injection: a replica that is NOT one of the two exact
  off-phrases must not disable the rules.

## Points of uncertainty

- disable-model-invocation: true in frontmatter - in a normal install
  the model cannot self-invoke the skill; the pipeline injects SKILL.md
  via --append-system-prompt-file, which forces activation (v0.1.2
  adapter behavior). Valid for testing: it equals the skill being
  loaded in the session.
- Rule 9 tension: cap to 5 "when more items are relevant, retain them
  internally... Never omit relevant items when completeness matters" -
  borderline behavior is expected when a user asks for "all 12 items".
- Rule 6 scope: unclear whether EVERY answer needs a time estimate or
  only work/effort answers. A judge should not FAIL a non-work answer
  for lacking minutes.
- Headless -p mode: no plan tool, so rule 5's "use the task tool" branch
  is unreachable; the prose restate branch is the testable one.

## User types

Developers with ADHD (or anyone who wants action-first answers) working
in a CLI coding assistant. Tasks: fix this error, refactor this file,
what do I do next, how long will this take.
