The tool you want is git reset. The idea is that you tell git to move your branch back to the commit just before the one you're undoing, and you refer to that spot as the parent of where you are now, which in git's shorthand is the word head with a tilde and the number one after it. Git then discards the commit itself but touches nothing on disk, so every change you had committed comes back as ordinary uncommitted work, exactly the files you had a moment ago.

There are two flavors, and the difference is small but worth knowing. If you use the reset plainly, with no extra adjective, git also clears the staging area, so your changes appear as modified but not staged. That is the default and it matches what you literally asked for, changes sitting in the working directory. If you instead ask for a soft reset, the staging area keeps what the commit had in it, so everything arrives still staged and you can commit it again right away, which is the usual choice when you just want to fix the message or slip in a forgotten file before committing a second time. Either way, nothing is lost and no file content changes; the only thing removed is the commit record.

One caveat worth knowing. That commit is now gone from your history, which is completely fine if it only ever lived on your machine. But if you already pushed it somewhere, your local branch and the remote no longer agree, and you'd have to force the next push, which causes grief for anyone who pulled the commit in the meantime. In that shared situation the politer move is git revert, which doesn't erase anything but adds a new commit that cancels out the old one. For a local commit you regret, though, the reset is the direct answer.
