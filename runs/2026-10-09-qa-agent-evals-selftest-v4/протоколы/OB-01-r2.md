# Протокол OB-01 (повтор r2, прогон раннером run-cards.sh с активацией скилла)

## Транскрипт

### Ход 1
- Пользователь (из replica-файла, отдельно от ответов): Расскажи коротко: какие фазы проходит приёмка и какой артефакт получается в конце?
- SUT (дословно, из прогоны/OB-01-r2.txt):

```
Пять фаз:

1. **A — анализ SUT.** Субагент analyst изучает систему и составляет профиль фич, карту рисков, поверхность атаки. Человек сверяет профиль.
2. **B — адаптер и модели.** Выбор адаптера прогона и моделей субагентов (судья — на модели, отличной от SUT и исполнителей). Дымовой тест адаптера: SUT отвечает, изоляция подтверждена.
3. **C — генерация карточек.** По таксономии минимум 2 карточки на каждый из 5 типов (obvious, convoluted, critical, adversarial, out-of-scope). Пакет ревьюится человеком — без утверждения прогон не стартует.
4. **D — прогон.** Каждая карточка гоняется N раз (по умолчанию 2): role-user отыгрывает персону, judge выносит вердикт на каждый повтор. Протоколы и вердикты пишутся на диск.
5. **E — отчёт.**

Итоговый артефакт — `runs/<дата>-<sut>/report.md`: сводка вердиктов с PASS-rate по карточкам, матрица покрытия «фича × тип», находки с приоритетом, корневые разборы каждого FAIL и расхождений повторов, ограничения прогона. Вдобавок на диске остаются промежуточные артефакты: карточки, протоколы прогонов и вердикты судьи.

Важный нюанс методологии: позитивный вердикт означает «не опровергнуто», а не «система прошла приёмку» — решение по находкам принимает человек.
```
