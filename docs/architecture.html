Checking one card runs through four named layers (borrowed from Inspect AI). A new check type is a new scorer: the pipeline itself does not change. The signal weakens from top to bottom; where a check can move up a layer, move it up.

1 · deterministic-scorer

scripts/check-facts.py · before the judge · zero cost

Matching of facts_must / facts_must_not against the transcript, the facts/ artifacts, and the det column in index.jsonl. A transcript match is proof (the leak is confirmed by grep); a protocol match is a candidate that the judge confirms or rejects. The judge receives the facts file and does not re-judge what is proven.

2 · model-graded-scorer

judge, step 1 · an LLM on a different model

Semantic scoring against the oracle. The input is isolated: oracle + protocol + the facts file of the deterministic layer, no persona and no instruction, so the judge does not know the card intent. The verdict scale (GOT / HONEST / PARTIAL / FAIL / ATTACK_PASSED) with explicit definitions lives in the judge system prompt (agents/judge.md): a contract, not model intuition.

3 · supervisor-scorer

judge, step 2

Supervision of the executor: did it hold the role, did it avoid helping the SUT, did it push the scenario to the end. INVALID only on explicit criteria, never on taste.

4 · reducer

orchestrator · repeat aggregation

majority (default) / unanimous / at_least(k). A repeat disagreement is a split: borderline behavior, the human decides. Committees soften noise, not correlated judge bias. A live run showed a nuance: a split can differ by sign (negative vs positive) or by label (ATTACK_PASSED vs FAIL with the same sign); telling the two apart is in the backlog.

P1 from research-rsi shipped (v0.3.0): grep-checkable facts moved out of the LLM judge into layer 1 (scripts/check-facts.py), after the HALO discipline "verify before you patch" and the verification hierarchy of the RSI survey.

All pipeline tuning is edits to these files. The when column names the moment the lever usually moves.

Approach

Acceptance testing with probes: not "run the prompts and look at them", but an oracle written in advance for every card, a judge on a different model, an isolated environment, and asymmetric conclusions. The grading criterion stays hidden from the system under test (the split of public and private signal, arXiv:2609.26457).

Verdict asymmetry

FAIL / ATTACK_PASSED prove a defect. A positive verdict only means "not refuted in N runs" (risk bounding), not "proven". The phrase «система прошла приёмку» is banned from reports.

Oracle before the run

Expectations and facts are fixed before the dialogue and never edited after it: the verdict cannot be fitted to the answer. Facts are binary (facts_must / facts_must_not), not graded.

Isolation by hierarchy

Executors do not know about each other; the judge does not see the card intent at step 1; the SUT session does not see the owner environment (a neutral cwd, no skills, no MCP).

Judge on a different model

A generator and a grader in one entity replicate their biases (arXiv:2607.07663). The routing: a headless call with an explicit --model, the choice agreed with the human at phase B.

Repeats and reducers

N runs per card (default 2; a split is a signal to raise it to 5 on critical and adversarial cards). Noise is the main threat to validity, averaging is mandatory.

A root cause for every negative verdict

FAIL / PARTIAL / ATTACK_PASSED get a review: the system broke it, the executor spoiled it, or the oracle itself was wrong. A marker proves that the output happened, not that the output stayed secret.

Subagents on demand

The orchestrator and the analyst spawn helpers for a task: one shared phase budget, each helper recorded in an artifact (who, why, what it read). The executor and the judge cannot: the measurement chain does not grow.

Dev/test discipline

A plugin fix found by self-acceptance closes only after a control run on an external SUT, otherwise it is overfitting to itself.

Placebo rule for improvement loops

After a harness optimization (the HALO class), validate only with fresh cards; the old set works as a regression smoke test. An improvement may follow the instruction rather than the evidence (+24 points on the placebo, arXiv:2607.07663).

Judge control, test control, det-layer control

Three controls guard the measuring chain. Judge: before an acceptance run the judge goes through a golden set with human reference verdicts (scripts/judge-control.py, threshold 6 of 8), and the verdict scale itself is a contract in the judge system prompt (agents/judge.md). Tests: mutation testing (mutmut 2.5.1) over the nine pipeline scripts, 1899 mutants; after nine new tests the kill score rose from 35.9% to 57.7% (docs/mutation-2026-11-12.md; a CI workflow with full and quick scopes keeps the run repeatable; survivors are information for the maintainers, not a gate). Det layer: marker fireability (facts/oracle-coverage.md); a must-marker that never fired is a dead-oracle candidate.
