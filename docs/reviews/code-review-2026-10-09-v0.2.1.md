## 1. Раннер — баги

**`.err` больше не содержит ошибок.** С `--output-format stream-json` сообщения вроде «Reached max turns», «API Error 4xx», «Not logged in» уходят в JSON-поток на stdout (events.jsonl), а не в stderr. Твоя таблица диагностики в adapters.md целиком читает `.err` — она теперь почти всегда пустая, и всё классифицируется как «Транскрипт пуст без ошибок → неопределённый». Диагностика сломана ровно в том релизе, где её добавили.

**Python падает, если events.jsonl нет** (claude не стартовал). `io.open(... .events.jsonl)` без try → исключение → ненулевой код → под `set -e` валит весь прогон на первой же сбойной карточке. Нужен guard на существование/пустоту файла.

**`type=result` как единственный источник текста.** При subtype=error result часто не строка (или отсутствует) → `.txt` пустой, хотя SUT ответил частично. А для max-turns это и есть типичный случай. Промежуточные assistant-text блоки игнорируются — теряешь ответ при любом не-идеальном завершении.

**`.prov.txt` всегда непустой** (`"\n".join(uniq) + "\n"`), `.txt` — пустой при отсутствии текста. Несимметрично; проверки `[ -s ]` на prov бессмысленны.

**`dict.fromkeys([])` + `seen.update` side-effect** — переусложнённая дедупликация ради того, что делает `dict.fromkeys(prov)`. Выкинь.

**ASP[@] под `set -u`.** В git-bash на Windows (bash 4.x) `"${ASP[@]}"` с пустым массивом = unbound error. Теперь ASP «ОБЯЗАТЕЛЬНА», так что в штатном пути не пусто, но любой не-скилл SUT или забытый `$6` даёт падение, а не внятную ошибку.

**cygpath-fallback корректен**, но python пишет по Windows-пути, а bash дальше проверяет `$out` по POSIX-пути — работает только если это один и тот же файл; на не-Windows без cygpath ок, но связь неявная и хрупкая.

## 2. Провенанс-правило судьи

«Факт без провенанса = кандидат на выдумку» систематически ложно-срабатывает:

- **Сам SKILL-SUT инъектируется через `--append-system-prompt-file`, а не через Read.** Все факты из инструкции SUT НЕ порождают tool_use → у них никогда нет провенанса → легитимное ядро системы помечается как выдумка. Это не edge-case, это норма для скилл-SUT.
- **Контекстное кэширование:** на ходах 2+ SUT не перечитывает уже прочитанный файл → провенанс пропадает на поздних ходах.
- **Не-Read источники:** WebFetch, MCP, Bash-cat, общие знания модели — вне твоего списка Read/Grep/Glob.

Правило годится только как «повод к scrutiny», и в тексте это оговорено — но судья получит шумный сигнал, где большинство флагов ложные. Нужно явно исключать факты из ASP-слоя.

## 3. Human-отчёт — упущено

- **Нет пробелов покрытия:** «чему верить с оговоркой» про N, но не про то, какие фичи/типы вообще не тестировались (а это первое, что нужно решателю).
- **Утечка секретов в цитатах.** ATTACK-карточки про выдачу ключей: «каждая находка с цитатой ответа системы» → в human-отчёт попадёт реальный ключ/секрет. Нужна редакция цитат.
- **Нет версии провенанса для человека:** предупреждение о marketplace-кэше (прогон шёл против другой версии) должно быть в human-отчёте жирно, иначе решение принимается по неверной версии.
- Сознательный отказ от «прошла/не прошла» разумен, но решателю не дан явный приоритет находок «блокер/терпимо».

## 4. Что сломается на чужом SUT

- **Хардкод `./`** в анти-дамп-правиле SKILL.md — неверный путь в любой другой среде.
- **`--append-system-prompt-file <SUT>/skills/<имя>/SKILL.md` объявлен ОБЯЗАТЕЛЬНЫМ** — ломает любой не-скилл SUT (бот/API/агент без такой раскладки). Противоречит собственной мультиадаптерности.
- **Калибровка golden-набором (6/8)** требует 8 кейсов с эталонными человеческими вердиктами для **незнакомого** домена — которых по определению нет на первой чужой приёмке. «Результат калибровки — первой секцией отчёта» становится блокером или пустой формальностью.
- **`run-integrity.sh` не в диффе** — существует ли? `md5` кроссплатформенно (md5sum/md5/certutil) — почти наверняка сломается вне твоей машины.
- **Проба моделей `claude -p --model X`** жжёт токены и завязана на конкретный шлюз (400 Unknown Model как «фильтр») — другое окружение ведёт себя иначе.
