# Mutation testing of the pipeline scripts (2026-11-12)

## What and why

Mutation testing checks the tests instead of the code. The tool (mutmut 2.5.1) makes one small change to a module at a time: flips a comparison, swaps `+` for `-`, replaces a number, wraps a string in `XX...XX`. After each change it runs the unit suite. A mutant that dies (some test fails) proves the suite notices that exact kind of fault. A mutant that survives means a fault no test notices: there is a hole in the tests at that line.

This is the same method the pipeline applies to everything else. Seeded defects against the SUT check that acceptance cards catch injected faults; the golden set checks that judge verdicts match human-approved references. Mutation testing turns the same instrument on the pipeline itself: the nine modules in `scripts/` that `tests/test_scripts.py` loads.

The point of the exercise: line and branch coverage only say that a line ran, not that anyone checked what it produced. A module can sit at 100% coverage while an inverted comparison in its report code goes unnoticed. The survivors below are concrete instances of that.

## The run

## Where the survivors are

All 1218 survivors were classified by cluster: source review of each cluster plus spot checks with `mutmut apply` (write the mutant, run the suite, restore). The split:

| Category | Count | Share | Meaning |
|---|---:|---:|---|
| Equivalent | ~145 | ~12% | Dead code or no behavior change; no test can kill these |
| Weak asserts | ~700 | ~57% | Behavior changes, a test runs, but it checks too coarsely |
| Holes | ~375 | ~31% | No test executes the code at all |

The category counts are expert estimates (accuracy about 5 percentage points); a per-mutant labeling of 1218 entries does not pay for itself.

Two mechanisms produce most of the survivors:

- mutmut 2.x wraps strings in `XX...XX`. The suite mostly checks output with `assertIn` (substring match), and a wrapped string still contains the original substring, so display-string mutants survive unless the string is a dict key or compared with `==`. String wrappers are 723 survivors (59%); most of them are output cosmetics (headers, labels).
- The main non-string cluster is code behind `main()`. The tests exercised the pure helpers (`parse_golden`, `run_stats`, `reduce_verdicts`) and almost never the `main()` of build-index, cost-report and judge-control: report rendering, path normalization, the agreement counter, the budget check. Those three functions alone account for roughly 300 surviving mutants.

Discounting the equivalent mutants, the score is about 39%; discounting the output cosmetics as well, about 55%. The raw 35.9% is the floor. The honest reading of the baseline: the four main scripts were tested as a library of pure functions, while `main()`, the part the user actually runs, was barely tested.

## Five findings

The raw score matters less than what the specific survivors show. The first four are faults no test noticed; the new tests kill each one. The fifth is a real bug in the code that the run surfaced.

**1. judge-control.py: inverted agreement with the reference** (mutant 457)

```diff
-        ok = (verdict == c["ref"])
+        ok = (verdict != c["ref"])
```

The control script would report agreement exactly when the judge failed the golden set, and disagreement when it passed. The module score was 17.3% because tests covered only `parse_golden` and `merge_golden`; the control run itself, whose result gates whether a judge model goes into acceptance, had no test at all.

**2. cost-report.py: minus instead of plus in the whole-run total** (mutant 736)

```diff
-                  "", f"**Прогон целиком: ${tot['usd'] + j['usd']:.3f}** "
+                  "", f"**Прогон целиком: ${tot['usd'] - j['usd']:.3f}** "
```

The headline number of the report would come out understated by twice the judge share, and every test would stay green.

**3. cost-report.py: overwrite instead of accumulate per card** (mutant 660)

```diff
-            c[k] += s[k]
+            c[k] = s[k]
```

With two runs of the same card, the per-card row would silently show only the second run's tokens, seconds and dollars; card totals would never add up to the run total.

**4. check-facts.py: swapped missing and leaked lists** (mutants 231, 233)

```diff
-            "missing": [m for m in must if m.lower() not in low],
-            "leaked": [m for m in must_not if m.lower() in low],
+            "missing": [m for m in must if m.lower() in low],
+            "leaked": [m for m in must_not if m.lower() not in low],
```

Markers present in the answer would be listed as missing, real leaks would vanish from the leaked list. `judge-batch.py` reads these lists when it picks candidates for auto-rejudge, so the inversion would corrupt the rejudge queue, not just the report.

**5. cost-report.py: dead POSIX branch, a live bug (fixed)**

The old `main()` normalized the path in the wrong order:

```diff
-    rd = a.run_dir.replace("/", os.sep)
-    if len(rd) >= 3 and rd[0] == "/" and rd[2] == "/":
-        rd = rd[1] + ":\\" + rd[3:].replace("/", "\\")
+    rd = norm(a.run_dir).replace("/", os.sep)
```

After the replace, a Git Bash drive path `/c/Users/...` has become `\c\Users\...` on Windows, so the `rd[0] == "/"` check can never fire. The branch was dead, glob found nothing, and every invocation from Git Bash produced an empty report. build-index.py and check-facts.py convert such paths correctly; cost-report.py did not. The 17 mutants inside the dead branch were counted as equivalent until the fix (`norm()` checks the drive prefix before the replace, commit `a0175aa`); a test that passes a `/c/...` path now covers them.

## How to reproduce

Local run on Windows, full set (about 40 minutes):

```
mutmut run --paths-to-mutate "scripts/check-facts.py,scripts/judge-control.py,scripts/cost-report.py,scripts/build-index.py,scripts/annotate-visuals.py,scripts/diff-runs.py,scripts/judge-batch.py,scripts/make-golden-truthfulqa.py,scripts/build-benchmarks.py" --runner "python -m unittest tests.test_scripts -q" --simple-output --no-progress
```

The cache lands in `.mutmut-cache` (SQLite, repo root). `mutmut show <id>` prints a mutant diff, `mutmut apply <id>` writes it to disk for manual experiments. After `apply` + `git checkout -- <file>`, delete `scripts/__pycache__`: the stale `.pyc` keeps the mutant's bytecode with a matching mtime, and the restored clean source runs the mutated code.

In CI: the Actions tab has a mutation workflow with a Run workflow button. Scope `full` mutates all nine modules, scope `quick` only judge-control, cost-report and check-facts. The per-module table lands in the step summary, the surviving mutants with diffs are uploaded as an artifact. Surviving mutants are information for the maintainers, not a gate: the workflow keeps the exit code at 0.

## What was adopted

Commit `a0175aa`:

- Nine tests in five new classes in `tests/test_scripts.py`: `JudgeControlMain` (agreement report, per-case verdict files, reuse of saved verdicts with `--only`), `CostReportMain` (per-card and judge aggregation, budget boundary, `norm()` including the POSIX path), `CheckFactsVerdicts` (all four DET verdicts, the missing/leaked lists, facts markdown content), `BuildIndexMain` (`norm()`, full index.jsonl rows), `DiffRunsFull` (closed negatives, split, counters).
- The `norm()` fix in cost-report.py (finding 5).

Commit `c834b9d`: `BuildIndexMain.test_index_rows` converted the temp dir to a Git Bash path unconditionally and broke on the Linux runner; the conversion now runs only for a Windows drive path.

Each draft test was checked both ways before landing: green on clean code, and lethal against its target mutants via `mutmut apply`. The suite went from 49 to 58 tests. A full mutmut rerun on the current tree will show how much the nine tests moved the score; until then, treat 35.9% as the pre-fix baseline documented here.
