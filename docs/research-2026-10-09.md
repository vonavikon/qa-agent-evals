# Открытые источники: что заимствовать в архитектуру (2026-10-09)

Вопрос: есть ли методы и модули для улучшения архитектуры qa-agent-evals. Краткий ответ: готовых модулей для встраивания мало (мы — плагин Claude Code, а не python-пакет), но четыре идеи из зрелых фреймворков стоят заимствования. Источники живы на октябрь 2026.

## Что показал обзор

**Три лидера фреймворков** ([сравнение DeepEval](https://deepeval.com/blog/top-5-llm-evaluation-frameworks), [benchlm-гид](https://benchlm.ai/llm-evaluation-frameworks)) различаются слоем, в котором живёт оценка: Promptfoo - конфигурация с assertion-проверками без судьи (дёшево, детерминированно), DeepEval - pytest-стиль с 50+ метриками и LLM-судьёй, Inspect AI (UK AISI) - архитектура Task = Dataset + Solver + Scorer с редьюсерами и перепросчитываемым логом. Наш конвейер - четвёртый вариант (agentic-оркестрация в самом Claude Code), ближайший родич - Inspect по структуре.

**Трейсинг стандартизуется**: OpenTelemetry GenAI semantic conventions ([обзор](https://opentelemetry.io/blog/2026/genai-observability), [семантика агентов](https://opentelemetry.io/blog/2025/ai-agent-observability)) задают модель «прогон = trace, вызовы = spans, токены = metrics»; Langfuse - популярный OTLP-бэкенд ([интеграция](https://langfuse.com/integrations/native/opentelemetry), [оценка агентов по трейсам](https://langfuse.com/resources/engineering/ai-agent-evaluation)). Техника replay - переоценка изменений по записанным трейсам без новых прогонов ([Kerno о воспроизводимости](https://www.kerno.io/blog/improving-trace-visibility-and-reproducibility-in-langfuse), [ZenML-сравнение](https://www.zenml.io/blog/opik-vs-langfuse)).

**Inspect-детали** ([scorers](https://inspect.aisi.org.uk/scorers.html), [multiple scorers + редьюсеры](https://inspect.aisi.org.uk/multiple-scorers.html), [metrics](https://inspect.aisi.org.uk/metrics.html)): scorer - первоклассный интерфейс (детерминированный / model-graded), редьюсеры `majority`, `at_least(k)`, `passk` агрегируют повторы, `.eval`-лог (JSON) позволяет пересчитать вердикты без повторных прогонов (с оговорками - [issue #5612](https://github.com/UKGovernmentBEIS/inspect_ai/issues/5612)).

## Что заимствуем (приоритет)

1. **Машиночитаемый лог прогона (по образцу .eval Inspect).** Сейчас артефакты - markdown, переиспользовать программно нельзя. Добавить `runs/<дата>-<sut>/index.jsonl`: по строке на прогон (id, тип, фича, вердикты повторов, редьюсер-итог, пути txt/prov/diag/вердикта, модель судьи). Это открывает re-scoring (пересуд без прогонов - наш «досуд» v1 стал бы командой), сводки и сравнение приёмок скриптом. Дёшево, максимум пользы.
2. **Явный редьюсер повторов (Inspect).** Заменить рукописный PASS-rate на именованные редьюсеры в oracle.md: `majority(N)` - итог за большинством (наш дефолт при N=2 это «единодушие или флаг»), `at_least(k)` для критичных карточек, `passk` для оценки частоты дефекта. Формализация уберёт двусмысленность «GOT 1/2».
3. **Scorer-интерфейс в архитектуре (Inspect).** Назвать слои явно: deterministic-scorer (grep facts - уже есть), model-graded-scorer (судья шаг 1), supervisor-scorer (судья шаг 2), reducer (агрегация повторов). Это переименование того, что есть, - но даёт язык и точку расширения (new scorer = new тип проверки без переделки конвейера).
4. **Провенанс как трейс (OTel-идея).** Наш events.jsonl + prov.txt - зачаток GenAI-трейса; держать поля (кто вызвал, что прочитано, сколько токенов) совместимыми по смыслу со span-моделью, чтобы при нужде экспортировать в OTLP/Langfuse без перекройки.

## Что НЕ берём

- Встраивание самих библиотек (DeepEval/promptfoo/Inspect) - другой рантайм (python против плагина Claude Code); наш конвейер агентский, у них - программный.
- CI-гейты и дашборды Langfuse - перегруз для пет-проекта; JSONL-индекс покрывает потребность.
- Датасет-реплей полного диалога - stateless-ходы уже дают изоляцию; пересуд по протоколам (re-scoring) закрывает сценарий дешевле.
