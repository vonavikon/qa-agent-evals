# qa-agent-evals v0.1: план реализации

> **Для исполнителя:** план выполняется задачами; шаги отмечаются чекбоксами. Спек — источник требований: `docs/spec.md` (утверждён после трёх проходов флагмана, читается вместе с планом). Метод: native (исполнитель — та же сессия, цель задана /goal).

**Goal:** собрать плагин Claude Code для приёмочного тестирования LLM-систем ролевыми субагентами (8 файлов пакета) и провалидировать его самоприменением: плагин тестирует сам себя полным конвейером фаз A-E.

**Architecture:** markdown-плагин без кода: скилл ведёт сессию-оркестратор по пяти фазам (анализ SUT, адаптер, карточки, прогон, отчёт); три субагента (analyst, role-user, judge) исполняют роли; три knowledge-файла несут таксономию, адаптеры и правила оракулов. Прогон: каждая карточка - субагент против SUT через headless `claude -p`; артефакты немедленно в `runs/`.

**Tech Stack:** плагин Claude Code (plugin.json + skills/ + agents/ + knowledge/), YAML-карточки, headless claude CLI, изоляция CLAUDE_CONFIG_DIR.

**Spec:** `docs/spec.md`

## Global Constraints

- Терминология фиксирована спеком и одинакова во всех файлах: типы `obvious | convoluted | critical | adversarial | out-of-scope`; вердикты `GOT | HONEST | PARTIAL | FAIL | ATTACK_PASSED | INVALID`, статус `NOT_TESTED`, пометка `LOW_CONFIDENCE`.
- Пять фаз конвейера называются: A анализ SUT, B выбор адаптера, C генерация карточек, D прогон, E отчёт.
- Оракул пишется до прогона; для obvious/critical/adversarial проверяемый факт обязателен; исключение - только convoluted/out-of-scope с oracle.note.
- Судья двухшаговый; вердикт шага 1 фиксируется до шага 2; INVALID - только по явным критериям контракта роли; следствие INVALID - перепрогон до 2 раз, затем NOT_TESTED.
- Асимметрия отчёта: негативный вердикт - доказательство дефекта, позитивный - «не опровергнуто»; формулировка «система прошла приёмку» запрещена.
- Изоляция: исполнители видят карточку и SUT; судья - протокол без persona/instruction; оркестратор - всё; артефакты в runs/ немедленно, в контексте только сводки.
- Все тексты на русском, инфостиль, без длинного тире и юникод-стрелок в тексте (в ASCII-схемах допустимо `-->`).

## Review Focus

1. Терминологический дрейф между файлами (шкала вердиктов, названия типов) - проверка Task 9 (grep-сверка всех файлов по спискам из Global Constraints).
2. Двухшаговость судьи теряет заморозку шага 1 - проверка Task 7 (grep «фиксируется» и порядок шагов в judge.md).
3. Frontmatter агентов и скилла не соответствует формату плагина (name, description, tools) - проверка Task 8-9 (структура полей).
4. Скилл-описание не содержит триггерных фраз из спека - проверка Task 8 (grep «приёмка», «acceptance»).
5. В self-приёмке изоляция qa-плагина в SUT-сессии ожидаемо нарушена (SUT = сам плагин) - проверка Task 10 (оговорка в отчёте self-test).
