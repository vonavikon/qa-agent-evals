# qa-agent-evals

[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Плагин Claude Code для приёмочного тестирования LLM-систем ролевыми субагентами. Вы указываете путь к тестируемой системе (SUT) — плагин строит её профиль, генерирует карточки-сценарии пяти типов, прогоняет их субагентами-исполнителями через изолированный адаптер, выносит вердикты судьёй на другой модели и собирает отчёт с PASS-rate и матрицей покрытия.

От ручного прогона промптов отличается тем, что у каждой карточки заранее записан оракул (facts_must / facts_must_not), судья закреплён за другой моделью, а среда изолирована от скиллов и MCP владельца. Вердикты асимметричны: FAIL доказывает дефект, GOT означает лишь «не опровергнуто».

![Конвейер: анализ SUT, карточки, изолированный прогон, судья, отчёты](assets/concept.gif)

*Пет-проект: цель — разобраться в приёмочных evals, метод — построить рабочий инструмент и прогнать его на самом себе.*

## Как это работает

```
[A: анализ SUT] → [B: адаптер + дым] → [C: карточки] → [D: прогон ×N повторов] → [E: отчёт]
```

- **Аналитик** (фаза A) читает SUT и строит профиль: реестр фич, карта рисков, поверхность атаки, точки неопределённости, варианты адаптеров.
- **Карточки** (фаза C) — 5 типов: obvious (happy path), convoluted (многоходовая неоднозначность), critical (зоны ущерба), adversarial (одна атака OWASP на карточку), out-of-scope (признаёт ли SUT, что запрос вне её зоны). Формат — YAML с персоной, инструкцией, оракулом (facts_must / facts_must_not + ожидание прозой) и бюджетом.
- **Исполнитель role-user** отыгрывает персону против SUT через адаптер. Для CLI-SUT это изолированная headless-сессия: нейтральный cwd, без скиллов и MCP владельца. Повторы — `scripts/run-cards.sh`.
- **Судья** работает в два шага и закреплён за другой моделью (`model:` в `agents/judge.md`): сначала оценивает ответ SUT по оракулу, не зная замысла карточки, затем проверяет, не подыграл ли исполнитель. Вердикты: GOT / HONEST / PARTIAL / FAIL / ATTACK_PASSED / INVALID.
- **Отчёт**: PASS-rate повторов, матрица покрытия «фича × тип», находки с приоритетами, разбор причин, ограничения прогона.

Схема работы, изоляция контекстов и матрица ответственности — в [docs/architecture.md](docs/architecture.md).

## Быстрый старт

Требования: Claude Code, bash, python3. На Windows — Git Bash или WSL.

Установите плагин (`--plugin-dir` или через marketplace), откройте сессию в каталоге тестируемой системы и напишите:

```
запусти приёмочное тестирование <путь к SUT>
```

Оркестратор проведёт фазы A-E сам и один раз остановится — перед утверждением карточек: покажет их вам и дождётся решения.

## Состав

```
.claude-plugin/plugin.json    манифест
skills/acceptance-test/       конвейер пяти фаз (оркестратор)
agents/analyst.md             профиль SUT
agents/role-user.md           ролевой исполнитель
agents/judge.md               двухшаговый судья (закреплён за другой моделью)
knowledge/taxonomy.md         5 типов карточек, паттерны, эталонный YAML
knowledge/adapters.md         CLI-адаптер и изоляция среды
knowledge/oracle.md           оракулы, шкала вердиктов, шаблон отчёта
scripts/run-cards.sh          CLI-раннер одноходовых карточек с повторами
scripts/run-integrity.sh      детектор вмешательства SUT в каталог прогона
scripts/parse-events.py       разбор events.jsonl: ответы, провенанс, диагностика
scripts/build-index.py        машиночитаемый индекс прогона (index.jsonl)
docs/spec.md                  спецификация
docs/plan.md                  план реализации
docs/architecture.md          схема работы: конвейер, изоляция, ответственность
docs/research-2026-10-09.md   разбор фреймворков-источников идей
docs/reviews/                 внешние ревью спеки и code-review
runs/                         артефакты самоприёмок (чувствительные данные вырезаны)
```

## Статус

v0.2.2. Конвейер прогнали на самом плагине четыре раза (самоприёмки v1-v4, отчёты в [runs/](runs/2026-10-08-qa-agent-evals-selftest/report.md)): v1 нашла 3 реальных дефекта — границы применения, обещание нереализованного, контроль утверждения; каждый следующий прогон проверял фиксы предыдущего и искал новые. После четвёртой — приёмка первой сторонней системы (корпоративная, детали приватны): конвейер отработал без настройки под неё.

Что пока не работает: реализован только CLI-адаптер; изоляция отрезает вызов скиллов, но не знание об их существовании; судью разводят вручную — CLI-вызовом с явной `--model` или выбором человека на фазе B, потому что поле `model` агента работает не во всех средах.

Спека — [docs/spec.md](docs/spec.md), план — [docs/plan.md](docs/plan.md).
