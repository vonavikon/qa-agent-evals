# qa-agent-evals

[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Плагин Claude Code для приёмочного тестирования LLM-систем ролевыми субагентами. Вы указываете путь к тестируемой системе (SUT). Плагин строит её профиль, генерирует карточки-сценарии пяти типов, прогоняет их субагентами-исполнителями через изолированный адаптер, выносит вердикты судьи на другой модели и собирает отчёт с PASS-rate и матрицей покрытия.

От ручного прогона промптов отличается тремя механизмами: у каждой карточки заранее записан оракул (facts_must / facts_must_not), за судьёй закреплена другая модель, среда изолирована от скиллов и MCP владельца. Вердикты асимметричны: FAIL доказывает дефект, GOT означает лишь «не опровергнуто».

![Как это работает: плагин изучает систему, придумывает задания, актёр играет пользователя, судья оценивает ответы, отчёт показывает результат](assets/concept.gif)

*Пет-проект: понять приёмочные evals, построив рабочий инструмент и прогнав его на самом себе.*

## Как это работает

```
[A: анализ SUT] → [B: адаптер + дым] → [C: карточки] → [D: прогон ×N повторов] → [E: отчёт]
```

- **Аналитик** (фаза A) читает SUT и строит профиль: реестр фич, карта рисков, поверхность атаки, точки неопределённости, варианты адаптеров.
- **Карточки** (фаза C) пяти типов: obvious (happy path), convoluted (многоходовая неоднозначность), critical (зоны ущерба), adversarial (одна атака OWASP на карточку), out-of-scope (признаёт ли SUT, что запрос вне её зоны). Формат: YAML с персоной, инструкцией, оракулом (facts_must / facts_must_not + ожидание прозой) и бюджетом.
- **Исполнитель role-user** отыгрывает персону против SUT через адаптер. Для CLI-SUT это изолированная headless-сессия: нейтральный cwd, без скиллов и MCP владельца. Повторы запускает `scripts/run-cards.sh`.
- **Судья** работает на другой модели (`model:` в `agents/judge.md`) и оценивает в два шага: сначала сверяет ответ SUT с оракулом, не зная замысла карточки, затем проверяет, не подыграл ли исполнитель. Вердикты: GOT / HONEST / PARTIAL / FAIL / ATTACK_PASSED / INVALID.
- **Отчёт**: PASS-rate повторов, матрица покрытия «фича × тип», находки с приоритетами, разбор причин, ограничения прогона.

Схему работы, изоляцию контекстов и матрицу ответственности смотрите в [docs/architecture.md](docs/architecture.md). Интерактивная версия: [docs/architecture.html](docs/architecture.html), для каждого узла показано, как на него влиять. Файл открывайте в браузере локально.

## Быстрый старт

Требования: Claude Code, bash, python3. На Windows нужен Git Bash или WSL.

Установите плагин (флагом `--plugin-dir <путь>` при запуске сессии или через marketplace), откройте сессию в каталоге тестируемой системы и напишите:

```
запусти приёмочное тестирование <путь к SUT>
```

Конвейер проведёт фазы A-E сам и один раз остановится перед утверждением карточек: покажет их вам и дождётся решения.

## Состав

```
.claude-plugin/plugin.json    манифест
skills/acceptance-test/       конвейер пяти фаз (оркестратор)
agents/analyst.md             профиль SUT
agents/role-user.md           ролевой исполнитель
agents/judge.md               двухшаговый судья (за ним закреплена другая модель)
knowledge/taxonomy.md         5 типов карточек, паттерны, эталонный YAML
knowledge/adapters.md         CLI-адаптер и изоляция среды
knowledge/oracle.md           оракулы, шкала вердиктов, шаблон отчёта
scripts/run-cards.sh          CLI-раннер одноходовых карточек с повторами
scripts/run-integrity.sh      детектор вмешательства SUT в каталог прогона
scripts/parse-events.py       разбор events.jsonl: ответы, провенанс, диагностика
scripts/build-index.py        машиночитаемый индекс прогона (index.jsonl)
docs/spec.md                  спецификация
docs/plan.md                  план реализации
docs/architecture.md          схема работы: конвейер, изоляция, ответственность
docs/research-2026-10-09.md   разбор фреймворков-источников идей
docs/reviews/                 внешние ревью спеки и code-review
runs/                         артефакты самоприёмок (чувствительные данные вырезаны)
```

## Статус

v0.2.4 (наследие v0.2.3). Конвейер прогнали на самом плагине четыре раза (самоприёмки v1-v4, отчёты в [runs/](runs/2026-10-08-qa-agent-evals-selftest/report.md)): в v1 нашлись 3 реальных дефекта (границы применения, обещание нереализованного, контроль утверждения); каждый следующий прогон проверял фиксы предыдущего и искал новые.

После четвёртой прогнали первую стороннюю систему (название не раскрываю): конвейер отработал без настройки под неё. Затем полная приёмка трёх сторонних плагинов (11.10.2026, 31 карточка × 2 повтора). Она вскрыла три дефекта самого конвейера: parse-events падал на событии с message-строкой, run-cards обрезал многострочные реплики, headless-судья уходил в инструменты и упирался в лимит ходов. Все три исправлены в v0.2.4.

Что пока не работает: реализован только CLI-адаптер; изоляция отрезает вызов скиллов, но не знание об их существовании; судью разводят вручную: CLI-вызовом с явной `--model` или выбором человека на фазе B, потому что поле `model` агента работает не во всех средах.
