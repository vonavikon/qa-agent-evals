# qa-agent-evals

Плагин приёмочного тестирования LLM-систем ролевыми субагентами. По профилю тестируемой системы (SUT) генерирует карточки-сценарии пяти типов, прогоняет их субагентами-исполнителями через изолированный адаптер, выносит вердикты двухшаговым судьёй на другой модели и собирает отчёт для человека.

![Конвейер: анализ SUT, карточки, изолированный прогон, судья, отчёты](assets/concept.gif)

## Как это работает

```
[A: анализ SUT] → [B: адаптер + дым] → [C: карточки] → [D: прогон ×N повторов] → [E: отчёт]
```

- **Аналитик** (фаза A) читает SUT и строит профиль: реестр фич, карта рисков, поверхность атаки, точки неопределённости, варианты адаптеров.
- **Карточки** (фаза C) — 5 типов: obvious (happy path), convoluted (многоходовая неоднозначность), critical (зоны ущерба), adversarial (одна атака OWASP на карточку), out-of-scope (честность границ). Формат — YAML с персоной, инструкцией, оракулом (facts_must / facts_must_not + ожидание прозой) и бюджетом.
- **Исполнитель role-user** отыгрывает персону против SUT через адаптер; для CLI-SUT — изолированная headless-сессия (нейтральный cwd, без скиллов и MCP владельца), повторы через `scripts/run-cards.sh`.
- **Судья** (двухшаговый): шаг 1 оценивает SUT по оракулу без знания психологии карточки, шаг 2 супервизирует исполнителя. Вердикты: GOT / HONEST / PARTIAL / FAIL / ATTACK_PASSED / INVALID. Судья закреплён за другой моделью (`model:` в `agents/judge.md`).
- **Отчёт**: PASS-rate повторов, матрица покрытия «фича × тип», находки с приоритетами, корневые разборы, ограничения прогона. Асимметрия: негативный вердикт — доказательство дефекта, позитивный — «не опровергнуто».

## Состав

```
.claude-plugin/plugin.json    манифест
skills/acceptance-test/       конвейер пяти фаз (оркестратор)
agents/analyst.md             профиль SUT
agents/role-user.md           ролевой исполнитель
agents/judge.md               двухшаговый судья (закреплён за другой моделью)
knowledge/taxonomy.md         5 типов карточек, паттерны, эталонный YAML
knowledge/adapters.md         CLI-адаптер и изоляция среды
knowledge/oracle.md           оракулы, шкала вердиктов, шаблон отчёта
scripts/run-cards.sh          CLI-раннер одноходовых карточек с повторами
docs/spec.md                  спецификация
docs/plan.md                  план реализации
docs/architecture.md          схема работы: конвейер, изоляция, ответственность, принципы
docs/reviews/                 внешние ревью спеки и code-review
runs/                         артефакты самоприёмок плагина (санитизированы)
```

## Быстрый старт

Установка как плагин Claude Code (`--plugin-dir` или marketplace), затем в сессии с каталогом тестируемой системы:

```
запусти приёмочное тестирование <путь к SUT>
```

Оркестратор проведёт фазы A-E, на утверждении карточек остановится и покажет их человеку.

## Статус

v0.2.2. Самоприёмка v1 (2026-10-08, отчёт в `runs/`): конвейер нашёл 3 реальных дефекта в самом плагине (границы применения, обещание нереализованного, контроль утверждения) — закрыты в v0.1.1. Ограничения: CLI-адаптер единственный реализован; изоляция отрезает вызов скиллов, но не знание об их существовании; разводка судьи — CLI-вызов с явной --model или выбор человека (фаза B), поле model агента работает не во всех средах.

Спека и план — в `docs/`. Пет-проект: изучение приёмочных evals через построение рабочего инструмента на себе.
