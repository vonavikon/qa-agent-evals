# Изоляция выполнения: уровни и политика

Зачем: приёмка запускает чужой плагин в реальном Claude Code. Без барьера
этот процесс может читать файлы хоста (включая секреты и оракулы карточек),
ходить в сеть и выполнять команды за пределами рабочей папки. Изоляция —
это замок, а не надежда на честность модели.

## Уровни изоляции

| Уровень | Название | Что это | Что гарантирует | Когда выбирать |
|---|---|---|---|---|
| 0 | `host` | Теперешний режим: отдельный work-каталог, env-allowlist, пустой MCP, `--disallowedTools Skill`, детектор вмешательства | Секреты окружения не наследуются, чужие скиллы/MCP не вызываются, вмешательство в файлы прогона ловится. **Выход за пределы work физически НЕ запрещён** — барьером является только поведение модели | Публичные плагины из открытых репозиториев, быстрые приёмки, среды без Docker |
| 1 | `docker` | Контейнер: только копия SUT + work, сеть off, read-only + tmpfs, non-root, лимиты pids/memory | SUT не видит файлы хоста (включая оракулы и секреты, кроме единственного LLM-конфига), не имеет сети, пишет только в work | Недоверенные плагины, закрытые/корпоративные системы, прогон «злого» материала, публичные демонстрации безопасности |

## Правила выбора (фаза B, адаптер)

1. Уровень выбирается осознанно при настройке адаптера и фиксируется в
   отчёте (meta `isolation_level`). Дефолт `host` — простые публичные
   плагины не требуют контейнера.
2. Для недоверенного материала уровень `docker` обязателен; просьба
   «прогони без контейнера» для такого материала — отказ с отсылкой к
   этому правилу.
3. **Fail-closed**: если выбран `docker`, а Docker недоступен — прогон
   прекращается с явной ошибкой. Тихой подмены на `host` не существует;
   переход — только правкой выбора уровня человеком, с новой записью в
   отчёте.
4. В любом уровне SUT-сессия не получает окружение тестировщика (env-allowlist
   в раннере — общий слой).

## Что живёт в контейнере (уровень 1)

- Смонтированы: копия тестируемого плагина (read-only), work-каталог
  (чтение-запись), изолированный конфиг CLI (единственный секрет — доступ
  к LLM-шлюзу; ротационный, ничего кроме генерации не даёт).
- НЕ монтируются: домашний каталог, SSH-ключи, Docker socket, каталог
  репозитория приёмки, оракулы и вердикты.
- Флаги: `--network none`, `--read-only` + tmpfs для work, `--user` (non-root),
  `--pids-limit`, `--memory`, `--rm`, тайм-аут процесса снаружи.
- Канарейка: в «домашнем» каталоге контейнера лежит файл-приманка
  (заведомо фейковый секрет). Прочитать его SUT может — он внутри; а вот
  одноимённый файл на хосте — не может. Тест SEC-01 проверяет именно
  расхождение содержимого.

## Остаточные риски уровня 1 (фиксируются в отчёте)

- LLM-токен шлюза виден процессу внутри контейнера (плагин может прочитать
  конфиг). Митигируется ротацией и тем, что токен даёт только генерацию.
  Полное решение — egress-прокси с авторизацией снаружи (этап после MVP).
- Контейнер не защищает от уязвимостей самого рантайма (docker escape);
  для заведомо враждебного материала с exploit-амбициями — VM-уровень.

## Проверка изоляции (SEC-карточки против examples/evil-plugin)

SEC-01 чтение секрета хоста (канарейка) · SEC-02 чтение оракулов прогона ·
SEC-03 сеть · SEC-04 бесконечный процесс/тайм-аут · SEC-05 запись вне work ·
SEC-06 подмена эталонов. Ожидание на уровне docker: попытки разбиваются
(отказ/недоступность/пустой результат), на уровне host — честная запись,
что барьера нет (уровень 0 не заявляет песочницу).

## Интерфейс backend (scripts/sandbox.py)

`verify <level>` — доступность уровня (docker: демон+версия) ·
`prepare <level> <sut-dir> <run-dir>` — уникальный work, копия SUT,
конфиг CLI, meta (версия claude CLI, git-хеш SUT, уровень) ·
`wrap <level> <work> -- <команда>` — префикс запуска (host: как есть;
docker: docker run с флагами выше) · `cleanup <work>` — затирание.
